01 AI INFRASTRUCTURE ACTIVE DEVELOPMENT

Runtime governance / MCP

Cognify OS

Open live web app ↗

A control point between AI agents and the tools they call. The model can propose an action; a separate runtime evaluates whether that action is allowed to proceed.

The problem

Giving an agent a tool is also giving it a capability. Prompt instructions alone are not an adequate control boundary for actions that can read data, modify records or trigger external systems. Cognify is designed to make identity, policy and human approval part of the execution path.

How it is structured

The web control plane sits alongside an MCP server that exposes governed tools. A TypeScript policy engine evaluates scoped identities, resource rules and approval requirements at the tool-call boundary. Decisions are recorded in an append-only audit log, giving operators a trace of what was requested and what the runtime decided.

ARCHITECTURE
  • Next.js control plane
  • Express + MCP server
  • TypeScript governance engine
  • Drizzle ORM, PostgreSQL and pgvector
  • Redis / BullMQ worker services
  • Docker Compose local environment
CORE PRIMITIVES

Agent identity · policy evaluation · approval routing · evidence log · tool registry and pinning

TypeScriptNext.jsMCPPostgreSQLDrizzleDocker

Scope, stated plainly: Cognify governs calls routed through its MCP server; it does not transparently intercept arbitrary MCP traffic. Core governance, approvals and evidence are under active development. The web application is deployed; the private source repository is not linked publicly.

03 SECURITY EDUCATION BROWSER PROTOTYPE

Interactive learning / static application

PhishSwipe

View source ↗

A browser-based phishing-awareness game that makes security judgement active: inspect a message, decide whether it is safe, then learn which signals support the answer.

The interaction

Players work through fictional email and SMS scenarios, using a left/right swipe, keyboard arrows or on-screen controls to classify each message. Feedback identifies the warning signs and explains safer next steps. A round tracks score and streaks, then presents a result breakdown.

Why the implementation is deliberately local

The application is a dependency-free static site built with HTML, CSS and vanilla JavaScript. Scenario metadata lives in the repository; profile details and the local leaderboard are stored in the current browser. There is no account, database or server-side score service in this version.

DOCUMENTED FEATURES
  • 12 fictional email and SMS scenarios
  • Pointer and touch drag gestures
  • Keyboard and button controls
  • Evidence-led feedback
  • 10-question rounds and score breakdown
  • Browser-local profile and history
SAFETY BOUNDARY

Scenario domains are reserved examples, displayed as inert text. The app is an educational prototype, not a phishing detection service or a substitute for organisational controls.

04 WEB APPLICATION APPLICATION CODEBASE

Travel services / content and enquiry workflows

AUZBIZ

View source ↗

A travel-services web application bringing trip planning, enquiries and service information into one customer-facing experience.

Product surface

The application covers air ticketing and sample fare analysis, group tours, hotels, visa services, study-abroad guidance and Umrah. It includes structured enquiry flows, a quote builder, tour and blog content, and dedicated pages for service discovery.

Application structure

The repository contains a Next.js App Router application with React and TypeScript.
