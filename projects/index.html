01AI INFRASTRUCTURE ACTIVE DEVELOPMENT

RUNTIME GOVERNANCE / MCP

Cognify OS

Open deployed web app ↗

A control point between AI agents and the tools they call. The agent proposes an action; a separate runtime evaluates the identity, scope and policy before dispatch.

The problem

Giving an agent a tool gives it a capability. Prompt instructions are not a reliable enforcement boundary for actions that may read data, modify records or trigger external systems. Cognify is designed to put policy evaluation at the point where a proposed tool call becomes an action.

System design

The product combines a Next.js control plane with an Express-based MCP server. The MCP server exposes governed tools such as context retrieval, action checks, action logging and outcome logging. A TypeScript rule engine evaluates scoped identity, resource access and approval requirements. Decisions are written to an append-only audit log so operators can inspect what was requested and what the runtime decided.

Engineering considerations

  • Keep the policy check separate from the agent's own reasoning.
  • Represent allow, deny and approval-required as explicit outcomes.
  • Consume one-time approvals safely before dispatch, then record the outcome.
  • Make local development and demo startup possible without optional billing or provider credentials.
DOCUMENTED ARCHITECTURE
  • Next.js control plane
  • Express + MCP server
  • TypeScript governance engine
  • Drizzle ORM + PostgreSQL + pgvector
  • BullMQ worker services
  • Docker Compose local environment
CORE CAPABILITIES

Agent identity · policy evaluation · human approval · evidence log · tool registry and pinning · behavioural signals

TypeScriptNext.jsMCPPostgreSQLDrizzleRedisDocker

Scope boundary: Cognify governs calls routed through its MCP server. It does not transparently intercept arbitrary MCP traffic. The web app is deployed; the private source repository is intentionally not linked publicly. Some controls and integrations remain under active development.

02PRODUCT / PLATFORM BUILDING

FOUNDER-LED PRODUCT / AUTOMATION

X.Group

Product site ↗Source ↗

An operating layer for growing firms, with a product direction focused on workflow automation, multi-tenant isolation and an operational control plane.

Product thesis

Business automation often ends up as a collection of disconnected flows and point integrations. X.Group is being shaped around the idea that workflows need an operating context: who owns them, which workspace they belong to, what they can touch and how their state can be understood.

Implementation

The public repository describes a Next.js App Router application written in TypeScript. Tailwind CSS is used for the UI, with Three.js / React Three Fiber and motion tooling for selected visual interactions. The project README documents Vercel deployment and an email integration configured through environment variables.

What matters next

The next test is not another layer of visual polish. It is whether a small, coherent workflow can be configured, executed, inspected and safely operated across a tenant boundary.

03SECURITY EDUCATION BROWSER PROTOTYPE

INTERACTIVE LEARNING / LOCAL-FIRST

PhishSwipe

View source ↗

A browser-based phishing-awareness game that asks people to make a judgement, then explains the evidence behind that judgement.

The interaction

Players inspect fictional email and SMS scenarios and classify each as phishing or safe. The interface supports pointer and touch swipes, keyboard arrows and on-screen controls. Feedback highlights the warning signs and explains safer next steps rather than only showing a right-or-wrong score.

Mechanics

A round contains up to ten scenarios. Correct answers earn points and streak bonuses; incorrect answers reset the streak. Results show a round breakdown. Profile and score history stay in the browser that was used to play.

Why local-first

The current version is a dependency-free static site. It does not need an account, database or API to run, which keeps the practice loop simple and avoids sending player history to a backend.

DOCUMENTED FEATURES
  • 12 fictional email and SMS scenarios
  • Touch, pointer and keyboard controls
  • Evidence-led feedback
  • 10-question rounds and score breakdown
  • Local profile and score history
  • Static GitHub Pages workflow
SAFETY BOUNDARY

Scenario URLs use reserved example domains and are displayed as inert text. This is a learning prototype, not a phishing detection system or a substitute for organisational security controls.

HTMLCSSVanilla JavaScriptLocal storageGitHub Pages

Scope boundary: no sign-in, cross-device sync, global leaderboard, email delivery or server-side scoring exists in this version.

04WEB APPLICATION APPLICATION CODEBASE

TRAVEL SERVICES / CUSTOMER JOURNEYS

AUZBIZ

View source ↗

A travel-services application that brings trip discovery, enquiries, service information and internal content workflows into one product.

Product surface

The codebase includes pages for flights, group tours, hotels, visa services, study-abroad guidance and Umrah. The customer journey includes enquiry capture and a quote builder, while content routes support tours and editorial posts.

Application structure

The repository contains a Next.js App Router application built with React and TypeScript, plus route handlers for flight and enquiry workflows, uploads and content. It also includes authentication and administrative screens for managing tours and posts.

Engineering focus

The main challenge is connecting a broad set of travel services into understandable journeys without implying that sample fare data is a confirmed booking or that visa outcomes can be guaranteed.

06WORKFLOW AUTOMATION PRODUCT EXPLORATION

PYFLOW / AI AUTOMATA

Visual workflow orchestration

Concept note / no public demo

An exploration of a visual automation environment where people can connect tools, agents and business processes through workflows that are inspectable and controllable.

Problem worth exploring

Automation becomes difficult to maintain when logic lives across disconnected scripts, integrations and agent prompts. A visual workflow model can make sequence, branching, dependencies and failure points easier to inspect.

Product questions

The exploration centres on node contracts, typed inputs and outputs, execution state, retries, reusable tool connections and human approval for high-impact actions. It could complement governed agent infrastructure, but it is not described here as an implemented product.

POTENTIAL COMPONENTS
  • Visual workflow canvas
  • Typed node contracts
  • Execution traces
  • Secrets and connector boundaries
  • Approval and retry policies
MATURITY

Product exploration. No production build, customer usage or public repository is claimed.

07COMMERCE / OPERATIONS PRODUCT EXPLORATION

KEBABLAB / RESTAURANT COMMERCE

Ordering beyond the menu page

Concept note / no public demo

A proposed restaurant ordering experience connecting customer checkout to the operational tools that staff need to fulfil an order.

Product direction

The idea moves beyond a brochure-style takeaway website. The customer side would need configurable items, option groups, combo rules, basket state and clear order status. The operational side would need a dashboard that can receive and manage the same order state.

System questions

Order lifecycle, menu availability, kitchen-facing status, notification delivery, upsell eligibility and analytics all need explicit rules. SMS and WhatsApp integrations would require real provider setup and should not be simulated in a portfolio demo.

PROPOSED SCOPE
  • Menu and modifier model
  • Combo and upsell rules
  • Order status and tracking
  • Staff administration
  • Notification integrations
  • Sales and operational analytics
MATURITY

Product exploration. This is not presented as a completed client delivery or live ordering platform.
